# MindReply — Public Presence Contract

## Position
MindReply should read as a serious human-communication infrastructure company, not as another generic AI wrapper.

## Vocabulary
Public language should prefer:
- communication systems
- follow-through
- response continuity
- human context
- verified action
- relationship memory
- operational clarity

Avoid unsupported superlatives, invented customer numbers, fake availability, fake certifications and claims that imply autonomous authority.

## Site architecture
The public site should answer five questions quickly:
1. What problem disappears?
2. Who is it for?
3. What actually happens after activation?
4. What is verifiably live today?
5. What can a buyer do next?

## SEO principles
- One canonical domain per public product where possible.
- Descriptive page titles and metadata.
- Stable canonical URLs.
- XML sitemap generated from real routes.
- robots policy that never blocks the canonical public pages accidentally.
- Structured data only for facts represented on the page.
- No doorway pages or keyword stuffing.

## Accessibility
The public site must support keyboard navigation, visible focus, reduced motion, semantic landmarks, readable contrast, descriptive labels and mobile touch targets.

## Reality rule
A route, feature, integration or certification is **live** only after a runtime check and an owner-visible evidence record. Otherwise label it planned, beta, private or unavailable.
